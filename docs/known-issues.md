# 已知限制

之後整理進 README 的「已知限制」。

## 非財務表格攤平後的數字仍留在內文 chunk

- **現象**：問「廣達每股盈餘」時，前 5 名裡有 2 個是廣達 p71、p72 的內文 chunk，內容是「股本形成經過」表攤平後黏在一起的數字，例如 `38,000,0003,363,00833,630,080`。正確的表格 chunk（p104 經營結果比較分析）排第 3 名。
- **原因**：ingestion 只會跳過「已抽成表格 chunk」的 bbox 範圍內的內文。股本表所在頁沒有財務概況關鍵字，項目欄也沒有財務項目，所以沒被抽成表格，攤平文字就留在內文裡。查詢裡的「每股盈餘」和表中的「每股面額」字面相近，因此排名偏高。
- **目前的處理**：接受現況。`/ask` 取前 8 名，表格 chunk 排在 context 最前面，prompt 要求數字以表格為準。
- **可能的修法**：全書用 pdfplumber 偵測格線表格的範圍，只用來排除內文（ingestion 會變慢，非財務表的內容也會從資料庫消失）；或偵測數字密集、數字黏連的 chunk 後丟棄或降權。

## 回答裡的引用編號 [n] 可能指錯段落

- **現象**：問「廣達 2025 年每股盈餘是多少？」，數字 19.45 元答對了，但有一次回答標成 [2]（p103 資產負債表）。數字其實出自 [1]（p104 經營結果比較分析）和 [3]（p5 致股東報告書）。temperature 0.1 下，同一題每次標的編號不一定相同。
- **原因**：[n] 是 qwen3.5:2b 自己寫的，小模型不一定照 prompt 規則把數字對應回正確段落。
- **影響範圍**：`sources` 事件由程式組成，編號與 context 的 [1]…[8] 一致，所以來源清單本身是正確的；只有回答文字裡的 [n] 可能指到錯的段落。
- **可能的修法**：評估階段（`eval/`）加一項引用正確率，檢查被引用的段落是否真的含有回答裡的數字；或由程式比對回答裡的數字出現在哪些段落，再自動標上或修正編號。
